---

## 1. Каркас: три слоя, одна программа

```
Слой 1 (compute)   аналитическая спека   — входы: counts / centrality / paths / co-occurrence / temporal
Слой 2 (novelty)   событийная спека      — что нового (first_seen) при формировании графа
Слой 3 (decisions) actionable-signals    — композиты / очереди / флаги поверх слоёв 1–2
```

Граница: Слой 1 = «посчитать по графу по запросу», Слой 2 = «извлечь и пометить новое при формировании графа», Слой 3 = «свернуть метрики в решения».

## 2. Два типа направлений развития

- **Build-out фазы** — как довести слои до существования: `v1a/v1b/v1c` (аналитика), `E1/E2/E3` (события), `P1–P4` (сигналы) — **10 фаз**.
- **Эволюционные арки** — куда слой растёт дальше: `Arc 1–6` (аналитическая спека §12) — **6 арок**.

Они переплетены (напр. `Arc 2` = события `E*` + сигнал `risk_score` + Temporal Schedule), поэтому ниже собраны в **волны**, а не читаются как три отдельных списка.

---

## 3. План по волнам

### Волна 0 — Фундамент (онлайн, без новой инфраструктуры, без LLM) 🟢

- **Что входит:** аналитика **v1a** (онлайн-ядро: семейства 1/2/4 + `personalized_pagerank` + чтение сообществ, планировщик, durable-воркфлоу, endpoint + MCP + CLI, полный provenance, eval на числовую верность; Cypher-фолбэк **off**) · события **E1** (миграция `first_seen` + граф-производные события + `new_events`/`entity_new_connections`) · сигналы **P1** (флаги качества знаний: противоречия, неполнота, орфаны, кандидаты-мерджи).
- **Что даёт:** аналитические вопросы по графу; видно, что нового появилось; ловятся противоречия/пробелы. Максимум ценности при минимуме стоимости — это MVP всей программы.
- **Зависимости:** schema-card из `schema.py` + крошечная миграция `created_at`. P1 едет на примитивах v1a.
- **Стоимость:** низкая.

### Волна 1 — Тяжёлый тир и композиты (нужна материализация) 🟠

- **Что входит:** аналитика **v1b** (`AnalyticsMaterializeWorkflow` — зеркало community-build + `top_central_entities` pagerank/betweenness/eigenvector + `link_prediction` + админ-триггер, опц. Temporal Schedule) · сигналы **P2** (композитный `risk_score` + лиды: investigate-next, review queue) · сюда же приземляются числовые роллапы из **Arc 1**.
- **Что даёт:** центральность/влияние, risk-скоринг с провенансом, очереди действий.
- **Зависимости:** P2 опирается на материализацию из v1b (centrality) и first_seen-всплески из Волны 0.
- **Стоимость:** средняя (офлайн-воркфлоу + GDS).

### Волна 2 — LLM-события и непрерывная разведка 🟠

- **Что входит:** события **E2** (структурные LLM-события: схема в `extract_kg` + резолюция/дедуп событий + `event_dossier`/`event_timeline`) · **Arc 2** непрерывный мониторинг + алерты (Temporal Schedule + dirty-mark, на `first_seen` и `risk_score`) · сигналы **P3** (доменные роллапы: Issue/Resolution, числа по `Amount`, коммуникации, тональность).
- **Что даёт:** богатые события со слотами; watchlist/алерты («новая связь у отслеживаемого», «вырос risk_score»); доменная BI. Превращает «спросил-ответил» в «система сама находит».
- **Зависимости:** E2 — правка LLM-пути ingest; Arc 2 — Schedule + Волны 0/1.
- **Стоимость:** средняя-высокая (LLM на ingest + резолюция событий — главный риск, см. событийную спеку §4).

### Волна 3 — Глубина интеллекта и доверие

- **Что входит:** события **E3** (burst/trending детектор + `trending_events`) · **Arc 3** (гибрид аналитика+поиск; многошаговое *верифицируемое* рассуждение plan-verify-refine; сравнения/counterfactual) · **Arc 4** + аналитика **v1c** (промоушен Cypher-фолбэков в примитивы; включение ограждённого text-to-Cypher после adversarial-тестов; калибровка/неопределённость).
- **Что даёт:** трендовые события; ответы «посчитай → докажи цитатами» одним запросом; самозаполняющийся каталог; доверяемые числа с предупреждениями о разреженности.
- **Зависимости:** Arc 3 переиспользует retrieval-слой; Arc 4 — логи фолбэков из v1a/v1c.
- **Стоимость:** высокая.

### Волна 4 — Охват и обогащение (far)

- **Что входит:** **Arc 5** (подграфы для визуализации, дашборды граф-здоровья/риска в Grafana, плановые дайджесты, разговорная аналитика) · **Arc 6** + сигналы **P4** (сверка с внешними реестрами через Wikibase-якорь: ИНН → офиц. данные; source-weighted рёбра; срез по department/tenant) · углублённый **Arc 1** (temporal-graph снапшоты, мотивы, структурные эмбеддинги `similar_entities`).
- **Что даёт:** визуализация, внешняя верификация «правды», продвинутые вычисления.
- **Зависимости:** Arc 6/P4 — заполненный Wikibase; Arc 5 — фронт.
- **Стоимость:** высокая, не на критическом пути.

## 4. Шесть эволюционных арок — суть

| Арка | О чём | Переиспользует | Волна |
|---|---|---|---|
| **Arc 1 — Глубже считать** | structural-эмбеддинги (`similar_entities`), числовые роллапы (мини-OLAP), temporal-graph снапшоты + change-point, мотивы (циклы владения, «звёзды» вокруг идентификатора) | GDS, материализация | 1 (роллапы) / 4 (остальное) |
| **Arc 2 — От Q&A к интеллекту** ⭐ | композитный `risk_score`, детекция аномалий, **непрерывный мониторинг + алерты** | Temporal Schedule + материализация + dirty-mark | 2 |
| **Arc 3 — Умнее планировать** | гибрид аналитика+поиск, многошаговое verified-рассуждение (не ReAct), сравнения/counterfactual, network-resilience | retrieval-слой, планировщик | 3 |
| **Arc 4 — Самоулучшение + доверие** | промоушен фолбэков в примитивы, eval числовой верности, калибровка/неопределённость | provenance-цепочка, eval-харнес | 3 |
| **Arc 5 — Поверхности и доставка** | подграфы для viz, дашборды, плановые дайджесты, разговорная аналитика | Grafana/Prometheus, Schedule, `history`/`contextualize_query` | 4 |
| **Arc 6 — Обогащение данными** | внешние реестры через Wikibase (ИНН → офиц. данные), source-weighted рёбра, department/tenant-срез | Wikibase populator + WDQS, метаданные документов | 4 |

## 5. Зависимости и горизонты

```
v1a ─┬─ v1b ─── P2(risk/leads) ─── Arc2(мониторинг) ─── Arc3 ─── Arc4
     ├─ P1(quality)                                      │
E1(first_seen) ─── E2(LLM-события) ─────────────────────┘
                   E3(burst) ── Arc1/Arc5/Arc6/P3/P4 (far)
```

| Горизонт | Волны | Содержание |
|---|---|---|
| **near** | 0 | v1a + E1 + P1 — онлайн-ядро, новизна, флаги качества |
| **mid** | 1–2 | материализация, risk/leads, LLM-события, мониторинг+алерты, доменные роллапы |
| **far** | 3–4 | hybrid/verified, самоулучшение, viz/дашборды, внешнее обогащение |

**Сквозная нить наибольшего рычага:** Волна 0 (фундамент) → **Arc 2** (мониторинг/риск — бьёт в identifier/due-diligence суть корпуса) → **Arc 3** (гибрид аналитика+поиск — уникальная ценность платформы) → **Arc 4** (самозаполняющийся каталог, сужает потребность в text-to-Cypher).
